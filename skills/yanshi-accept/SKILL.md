# 业务验收

> 依据 原文材料「四、五」与 Skill 结构材料。材料结构与人工状态细则为「推断」。

1. 接收验收契约、当前改动、自测、E2E 和审查结果。只准备当前范围的材料；不需要业务判断且材料已充分时可跳过。
2. 先看验收目标，再对应测试证据和核心实现，检查它们是否真的回答需求。代码与测试可能一起误解需求；预期结果来自业务契约，工具只负责提供证据。
3. 标出高风险业务路径和新增机制，说明尚未验证的风险。需要人的判断时提供可核对材料，等待真实反馈；反馈未到保持待判断，不代替人确认。
4. 本次需要 PR 描述且策略允许时：`Call the Skill tool with "pr"`。没有 Skill 调用器时，读取同套件的 `../pr/SKILL.md` 并按其执行。。缺失或受限时，本地写明变更目的、范围、验证结果与风险。撰写描述不自动包含创建、提交、合并或发布授权。
5. 完成检查：每个本次验收目标对应证据或明确缺口；已确认、待判断与未验证分开。输出业务验收摘要或按需保存 `acceptance.md`。材料整理完成与业务验收获批是两个不同结果。
6. 单独使用到此结束；提示见 [prompts.md](prompts.md)。
