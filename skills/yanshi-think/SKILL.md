# 想清楚

读 [project-context.md](project-context.md)，以 `[偃师·想清楚]` 开头，说清这次要厘清的一个问题。

1. 结合需求材料、用户反馈、已有 `CONTEXT.md` 和代码，把目标、范围、边界与取舍问清楚。能从材料查到的先查，不让用户重新口述。
2. 当剩余问题已经不会显著改变实现方向和验收结果时结束对齐，不要求预先穷尽实现细节。成熟的小改动给出做法即可。
3. 对有实质取舍的方案，优先寻找能推翻核心假设的反例；新增机制过多时，在满足需求的前提下删除非必要机制。
4. 简单需求直接给下一步；复杂需求拆成边界清楚、可独立验收的小增量。只有能独立推进的部分才并行，主 Agent 负责最终集成。

需要后续实现者与审查者共享上下文时，将问题、范围、关键决策和验收标准写入已有 Spec 或 `CONTEXT.md`；不为了调用过本入口而新建文件。只讨论方案时交付方案，不自动改代码。验收标准来自业务规则，不由当前实现倒推。
