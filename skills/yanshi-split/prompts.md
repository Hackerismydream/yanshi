# 拆分提示词

原文流程的可执行整理：。任务格式为。

```text
用 yanshi-split 拆分 <需求或方案位置>。
按可独立验收的业务小增量拆，不按前端、后端、数据库机械分层。
每项写清目标、范围、验收结果、依赖和集成责任。
只标出真正能独立推进的并行部分；没有并行能力就顺序推进。
保持每次变更便于理解和审查。这里只输出任务，不启动实现或创建远端任务。
```

最小任务格式：

```text
增量：<名称>
业务结果与契约：<完成后用户得到什么，依据是什么>
修改边界：<涉及和不涉及的部分>
验收目标：<怎样判断本增量成立>
依赖与阻塞：<先后关系>
执行与集成责任：<当前执行者或待分配>
并行判断：<可并行理由，或顺序执行>
```
