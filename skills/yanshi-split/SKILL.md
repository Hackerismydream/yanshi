# 任务拆分

> 依据 原文材料「二」与 Skill 结构材料。独立拆分入口与模板细则为「推断」。

1. 接收目标、方案与当前进度。任务足够小或已有有效拆分时，直接返回当前增量，不另建任务列表。
2. 可调用且策略允许时：`Call the Skill tool with "to-tickets"`。没有 Skill 调用器时，读取同套件的 `../to-tickets/SKILL.md` 并按其执行。。缺失、受限或任务系统未配置时，在本地按可独立验收的 tracer bullet 拆分，写明目标、边界和阻塞关系。
3. 只将能独立推进的工作并行化；按实际能力使用子 Agent 与隔离 worktree，由主实现者集成。能力不足或共享变更无法隔离时顺序执行。
4. 完成检查：每个增量都有可检查的业务结果、范围和依赖，集成责任清楚；并行部分不靠相互覆盖工作来推进。输出已有任务更新或按需保存的 `tickets.md`，创建远端任务另按授权处理。
5. 单独使用只交付拆分，不启动实现。提示与最小任务格式见 [prompts.md](prompts.md)。
