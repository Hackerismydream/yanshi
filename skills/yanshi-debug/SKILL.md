# 先看到哪里不对

读 [project-context.md](project-context.md)，指出当前有证据的偏差；原因未知就写未知。

先把业务契约规定的结果与实际失败放在一起，用项目已有入口复现相关路径。按场景取证：本地测试或编译失败，看失败输出和相关代码；涉及持久化状态时查库确认数据；跨服务或线上问题再看日志或 Trace。预期来自契约，不从一个看起来合理的返回值倒推。

启动、身份和查询方法先查项目现有资料与匹配的项目经验；缺入口、权限或复现材料时，指出缺的是什么。回到问题为什么发生和最小必要修改，而不是沿着“再加一层机制”继续排查。

有修复授权时修复并重新验证相关路径；只要求定位时，给出已确认的偏差、证据和还没查清的部分。保留本次失败与修复后的结果；用户要求沉淀时交给 retro。
