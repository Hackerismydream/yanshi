# 先看到哪里不对

读 [project-context.md](project-context.md)，以 `[偃师·排障]` 开头，指出当前有证据的偏差；原因未知就写未知。

先把业务契约规定的结果与实际失败放在一起。用项目已有入口运行相关路径，读取当前状态；查库确认数据，查日志或 Trace 看链路，不从一个看起来合理的返回值定义正确答案。

需要取得的启动、身份和查询方法，先查项目现有资料及匹配的项目经验。没有真实入口、权限或复现材料时，指出缺的是什么，不生成假命令或编造根因。不要沿着“再加一层机制”的既定答案排查；回到问题为什么发生和最小必要修改。

有修复授权时，由主实现者修复并重新验证相关路径；只要求定位时，给出已经确认的偏差、证据和还没查清的部分。日志解释不了的原因不写成结论。

保留本次失败与修复后结果。只有用户要求沉淀时才交给 retro；没有真实翻车与验证记录，不新增项目“常见坑”。
