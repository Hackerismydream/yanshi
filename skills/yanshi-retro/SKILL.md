# 复盘与减法

> 来源见 README「来源」小节；本文件的复盘格式与检查方式为（推断）。

1. 接收任务结果、实际问题、验证证据和现有流程。没有值得复用或删减的内容、也没有复盘请求时跳过。
2. 可调用且策略允许时：`Call the Skill tool with "retro"`。没有 Skill 调用器时，读取同套件的 `../retro/SKILL.md` 并按其执行。。缺失或受限时，从实际发生的决策、失败、修复和验证中总结有效做法与认知变化。
3. 对反复执行的稳定 SOP 考虑沉淀；原文建议流程重复超过三次可考虑做成 Skill，这不是强制次数门槛。稳定操作可脚本化，可工具化能力可封装为 CLI 或 MCP。
4. 复查现有 Skill 与工作约束，删除已无收益的步骤；沉淀 E2E SOP 时保留契约决定预期的边界，不把旧返回值保存成正确答案。
5. 完成检查：建议对应实际证据，区分“已验证有效”与“待试验”；说明复用或删减什么及如何观察效果。输出复盘摘要，确有需要才更新 SOP、Skill 或 `retro.md`。
6. 单独使用到此结束；提示见 [prompts.md](prompts.md)。

## E2E SOP 沉淀模板

见同目录 `e2e-sop-template.md`。它记录入口、环境准备、目标模板、取证方式、清理和已知失败模式。契约决定预期，工具只提供证据。
