# 验一下

读 [project-context.md](project-context.md)，说清本次检查的业务目标与实际入口。

先看验收标准，再看已有测试结果与核心业务逻辑。判断这些测试是否验证了需求真正关心的事，而不只看通过数量。

模式稳定的小改动，检查变更和相关自测即可；涉及权限、状态变化、并发、重试、一致性、迁移或回滚时，沿相应业务路径核对。需要确认真实入口和最终结果，或用户要求 E2E 时，读 [e2e.md](e2e.md)。预期来自业务契约，工具只提供证据。

只要求审查时保持只读。执行验收前确认环境与允许的副作用；证据不足就标为未验证。

需要交叉审查且有其他 Agent 时，交出同一份需求、变更和证据，让它检查核心业务逻辑与新增机制；没有其他审查者就说明是自查。问题交回主实现者修复并复验。

结尾列实际发现、证据、未验证风险和需要人判断的业务问题。需要保存证据时用 [evidence-template.md](evidence-template.md)。
