# 验一下

读 [project-context.md](project-context.md)，以 `[偃师·验一下]` 开头，说清本次检查的业务目标与实际入口；不是默认跑完整测试套件。

先看验收标准，再看已有测试结果与核心业务逻辑。判断这些测试是否回答需求真正关心的问题，而不只看通过数量。

模式稳定的小改动，检查变更和相关自测即可；涉及权限、状态变化、并发、重试、一致性、迁移或回滚时，沿相应业务路径核对。需要确认真实入口和最终结果，或用户明确要求 E2E 时，读取 [e2e.md](e2e.md)。契约缺失的目标保留缺口；工具提供证据，不定义预期。

用户只要求代码审查时不自行写数据。执行验收前确认环境与允许的副作用；证据不足说明未验证，不把代码审查写成 UI 或持久化通过。

需要交叉审查且有其他 Agent 时，交出同一份需求、变更和证据，让其检查核心业务逻辑与新增机制。没有其他审查者就说明是作者自查，不伪装独立审查。问题统一返回主实现者修复并复验。

结尾列实际发现、证据、未验证风险以及需要人判断的业务问题。审查结束不包含创建提交、合并、发布或替人批准。需要保存证据时用 [evidence-template.md](evidence-template.md)，短任务直接回复。
