# 交叉审查

> 依据 原文材料「二、四」与 Skill 结构材料。独立性标记与问题记录为「推断」。

1. 接收契约、变更、规范与已有验证结果。任务简单且本次未要求交叉审查时可跳过；单独调用默认只读。
2. 有其他 Agent 时按需分派审查。可调用且策略允许时：`Call the Skill tool with "code-review"`。没有 Skill 调用器时，读取同套件的 `../code-review/SKILL.md` 并按其执行。。缺失、受限或无子 Agent 时，按需求与规范两个维度本地审查；新会话复查和作者自查分别标明，不称为其他 Agent 的独立交叉审查。
3. 优先找推翻关键假设的反例，沿业务路径检查权限、状态、并发、重试、一致性、迁移与回滚。对新增抽象用奥卡姆剃刀，对职责边界用高内聚、低耦合原则。
4. 完成检查：每个已确认问题指向契约、变更位置或运行证据，并解释影响；证据不足的问题标为待核实风险。返回审查身份、发现、未覆盖部分和处理建议，按需保存 `review.md`。
5. 将问题交回主实现者；获准修复后依据受影响范围复验。单独审查可在交付发现后结束，不等待所有修复才交付审查结果。提示与问题格式见 [prompts.md](prompts.md)。
