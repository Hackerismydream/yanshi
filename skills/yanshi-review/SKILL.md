# 独立审查的交接与闭环

输入：业务契约、待审变更、实际验证记录，以及本次可用的审查者。默认只读。

1. 按 [handoff-template.md](handoff-template.md) 固定待审版本和未提交变更，交接契约与证据位置。不要把“实现者认为已通过”当作审查依据。
2. 有另一位审查者时，让其先读验收目标与变更，再看实现者解释。只有当前 Agent 时，明确记录作者自查；换会话记录新会话复查，不称为独立交叉审查。
3. 沿本次业务路径选具体反例：权限与身份是否匹配；状态转换是否满足前置条件；重复请求是否产生额外副作用；并发是否破坏约束；迁移或回滚是否丢失数据。只有变更涉及相应风险时才展开。
4. 检查证据是否回答契约，而不只看检查是否绿灯。新增机制说不清保护的约束时，要求解释必要性或提供更小替代，不凭代码量要求重构。
5. 每个确认问题写清契约、位置、反例和证据；没有足够证据的项标为待核实风险。没有发现问题时，列出已审路径和未覆盖范围，不写“没有风险”。
6. 将发现统一交给主实现者修复。固定修复后版本，重跑受影响检查；将新结果关联到原发现，不覆盖原失败。没有修复授权时交付审查结果即结束。

审查完成指材料与发现已交付；发现关闭需要复验证据。需人工接受的业务风险保持待决定，Agent 不代签。
