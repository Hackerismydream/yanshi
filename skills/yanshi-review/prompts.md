# 审查提示词

## 攻击关键假设

第一句为原文直接引用，其余为。

```text
对这个方案做一次对抗性审查，优先寻找能推翻核心假设的反例。
结合 <契约、变更与证据位置> 审查它的实现。
优先关注权限、状态变化、并发、重试、数据一致性、迁移与回滚。
把确认的问题与待核实风险分开，说明具体位置、影响、依据和建议验证办法。
本次只读，不修复或发布；明确本轮是否真的使用了其他审查 Agent。
```

## 职责边界

将原文的具体模块替换为参数：。

```text
按高内聚、低耦合原则审查 <目标模块> 的职责边界，不要为了拆而拆。
```

问题记录为「推断」：

```text
发现：<问题或待核实风险>
影响：<会违背什么业务目标>
依据：<契约、位置或运行证据>
反例或验证办法：<如何确认>
处理状态：<待修复 / 已修复待验证 / 已复验 / 待决定>
独立性：<其他 Agent / 新会话复查 / 作者自查>
```
