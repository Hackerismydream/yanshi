# 端到端验收

> 依据 E2E 材料 正文及评论，契约原则与环境能力依据 原文材料「三」。操作细则与模板为「推断」。

1. 接收自然语言最终目标、业务契约、待测版本、真实入口和授权。已有有效证据足够且用户未要求重跑时可复用；不适用时说明跳过。
2. 按 [goal-template.md](goal-template.md) 明确每个 case 的验收目标，选择适用的信息查询、多轮交互或状态修改及持久化任务。例子见 [goal-examples.md](goal-examples.md)。已有可信契约无需重复问人；没有契约时只交付待确认目标，或在授权内做明确标注的探索。
3. 按 [capabilities.md](capabilities.md) 确认环境、身份、数据起点、操作与取证能力；只准备本次需要的部分。缺少能力时缩小已声明的验证范围，或将受影响目标标为阻塞。
4. 让 Agent 从实际业务入口完成任务，自行选择必要页面、API 或 CLI 操作。观察中间状态与结果；不以生成传统测试用例或预写完整浏览器脚本作为前置步骤。稳定 SOP 可直接复用。
5. 对照事先确定的业务预期取证：页面或响应说明可见行为，独立再次读取与只读数据查询按契约确认持久化，日志和 Trace 解释链路。预期结果来自业务契约，工具只负责提供证据。
6. 按 [evidence-template.md](evidence-template.md) 判定并报告；每个已宣称满足的目标都有契约依据和当前运行证据。证据不足不算通过；修复、重试或契约变更保留关联的新记录。
7. 失败时返回目标、实际偏差和证据；默认验收不修代码，获准修复后重验受影响路径。按环境约定清理或重置，并单列清理结果。
8. 需要选组合时使用 [comparison-template.md](comparison-template.md) 同时比较通过率、耗时、成本；需要复用时提出稳定 SOP 的沉淀候选。单独使用到本次验收报告结束；入口提示见 [prompts.md](prompts.md)。
