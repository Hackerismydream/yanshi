# 自然语言验收目标

最终目标：让 <身份> 从 <真实入口> 完成 <业务任务>，得到 <用户需要的结果>。
契约依据：<条款、版本及位置>。
实现与环境：<版本、未提交变更、部署和数据起点>。
授权边界：<可以操作的对象与副作用>。

## 每个 case

- Case ID：<标识>
- 业务意图：<要完成什么，而不是固定点击顺序>
- 前置条件：<身份、权限、输入、已有状态与必要对话背景>
- 契约规定的结果：<最终答案、可见内容或状态>
- 必须保持的约束：<其他条件与禁止副作用；只写契约明确要求的内容>
- 证据需要：<页面行为、响应、独立回读、链路或答案依据>
- 终态与等待边界：<契约约定；不涉及等待则写不涉及>
- 决定正确性的未决项：<缺口；没有则写无>

## 三类目标怎样写

信息查询：写明身份可见范围、筛选条件和结果应满足的业务规则。空结果不自动正确，数量相同也不自动等于内容正确。

多轮交互：写明哪些条件在后续轮次必须保留，哪些被新指令覆盖。最终结果同时满足仍有效的条件；时间窗口沿用已确认时区与边界。

状态修改及持久化：写明目标对象、合法状态转换、不得影响的对象，以及独立回读后仍应保持的状态。只显示成功不满足持久化目标。

运行前固定预期。观察揭示契约需要修订时，记录修订理由与新版本，重新验收；不追认旧结果通过。草稿不能直接作为正式正确答案。
