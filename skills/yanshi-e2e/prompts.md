# E2E 提示词

## 单次真实验收

根据帖子及评论整理；参数化、范围和记录要求为「推断」。

```text
用 yanshi-e2e 验收 <功能或业务路径>，这次不修改代码。
最终目标：<用户要完成的结果>。
业务契约：<已确认的规则和来源>。
测试入口与身份：<环境、权限和数据起点>。
允许的状态修改与清理范围：<授权>。
先明确每个 case 的验收目标，再让 Agent 在真实环境里实际操作、读取状态并取证。
不用先写一套常规测试用例或浏览器脚本；操作路径由执行时观察决定。
预期来自业务契约，不从系统实际返回反推。
返回每个目标的实际结果、证据、失败或未验证部分，以及清理结果。
```

## 契约尚不完整时探索

「推断」。

```text
目前只有这个目标草稿：<草稿>。
在 <授权环境与操作范围> 内探索实际业务路径，记录观察到的状态和契约缺口。
这不是正式验收；不要把观察结果变成正确答案，也不要宣布通过。
最后只提出会影响验收判断的待确认问题。
```

## 比较候选组合

三个维度来自帖子；比较口径为。

```text
用同一组已确认的自然语言验收目标比较 <候选能力组合>。
保持业务契约、系统版本、测试身份、数据起点和计时口径可比。
重复次数、预算和并行方式按 <本次约定> 执行。
同时报告通过率、耗时和模型成本；保留失败、阻塞、重试和未知值。
不要仅凭成功样本的速度，或无法核对的成本，给出最优结论。
```
