# 方案设计

> 依据 原文材料「一、二」与 Skill 结构材料。独立入口和设计细则为「推断」。

1. 接收目标、约束、契约和当前实现。成熟模式已经满足需求、没有值得验证的新假设时，说明沿用理由即可跳过设计。
2. 选最小必要方案；怀疑问题定义时用第一性原理，新增机制过多时用奥卡姆剃刀。关键事实需要外部核实时：`Call the Skill tool with "research"`。没有 Skill 调用器时，读取同套件的 `../research/SKILL.md` 并按其执行。。缺失或受限时，查可访问的一手资料，区分事实与未核实假设。
3. 对核心假设做对抗性审查，优先找能推翻方案的反例。发现实质问题就修订；有其他审查 Agent 时按需使用，没有则标为同一 Agent 的方案自审。
4. 需要整理 Spec 且调用策略、授权与产物位置允许时：`Call the Skill tool with "to-spec"`。没有 Skill 调用器时，读取同套件的 `../to-spec/SKILL.md` 并按其执行。。缺失、受限或会附带未授权发布时，本地整理问题、范围、方案、取舍和验收目标。
5. 完成检查：方案覆盖目标，关键假设有依据或明确验证办法，重大反例已有处理或标为阻塞。按需定稿已有 Spec 或 `spec.md`；仅有方案不代表机制已实测。单独使用到此结束；提示见 [prompts.md](prompts.md)。
