# 动手，写完顺手测

读 [project-context.md](project-context.md)，以 `[偃师·动手]` 开头，用一句话说明当前改动与对应检查。

按已明确的需求做小范围变更。简单的直接实现；已有复杂任务拆分时推进当前增量，只有独立部分才交给其他 Agent 在不同 worktree 中做，主 Agent 集成。

写完先完成相关自测。能由类型检查、测试和业务断言发现的问题，尽量在交付前处理。检查命令从项目已有文档、manifest、脚本或 CI 中读取，不假造项目命令；没有执行条件就列明没测到什么。

发现过度设计时清理非必要机制。修复已知问题后重新验证；遇到原因不明的失败，保留失败信息，转入本次排障而不是继续堆改动。只修改已授权范围。

交付改动、实际检查结果和仍需真实环境验证的业务目标。测试绿灯不自动证明需求理解正确，也不等于 E2E 已通过。小任务不增加报告文件，只有用户或现有项目约定需要时落盘。
