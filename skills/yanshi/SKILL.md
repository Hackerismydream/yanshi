# 选择下一步

> 编排与调用细则为「推断」。步骤依据原文日常开发流程；按需读取 [routing.md](routing.md)。

1. 接收用户目标、已有材料、当前实现、验证证据和授权范围。复用有效上下文；只补会改变下一步的缺口。
2. 按 `routing.md` 选择当前最有价值的一步，说明要做什么、为何跳过其他相关步骤。简单任务可直接实现并自测，已有实现可直接验证。
3. 按名称调用所选子 Skill；没有调用器时，读取同套件的对应 `SKILL.md` 并按其执行，仍不可用则执行路由表同一行的最小等效动作。一次委派一个 Skill；独立子任务可由实现环节按能力并行。
4. 用本步产物检查退出条件，再决定继续、回退、跳过或停问。修复后按影响范围更新验证，不把单项自测替代失效的 E2E 证据。
5. 在用户请求的范围内结束：报告实际完成、跳过、未验证和待判断事项。只有本次选用目标有证据支持时才宣称相应目标完成。预期结果来自业务契约，工具只负责提供证据。
6. 需要恢复或换会话时使用 `yanshi-handoff`；需要落盘时参考 [state-template.md](state-template.md)，不为短任务补空记录。可复制入口见 [prompts.md](prompts.md)。
