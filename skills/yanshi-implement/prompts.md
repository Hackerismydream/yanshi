# 实现提示词

以下为，依据原文的小范围变更、主实现者集成和修复方式。

```text
用 yanshi-implement 实现 <任务或方案>。
验收依据是 <契约>，允许修改的范围是 <范围>。
选择最小必要实现，不为了完整添加暂时用不到的机制。
已有拆分时只推进当前增量；真正独立的任务才并行，由你负责集成。
返回变更、实际检查结果、未验证项和后续验证建议，不把“代码写完”说成“验收通过”。
```

```text
修复这个有证据的问题：<失败目标与证据位置>。
先区分契约、实现和环境原因，原因不清时用最小实验区分假设。
只修改 <授权范围>。修复后说明受影响的自测、审查和 E2E 范围。
保留原失败记录；验证未执行的部分明确标出来。
```
