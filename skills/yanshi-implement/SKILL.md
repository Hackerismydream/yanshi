# 编码实现

> 依据 原文材料「二」与 Skill 结构材料。委派裁剪和实现检查细则为「推断」。

1. 接收明确目标、契约、修改边界和已有方案。已有实现或本次只要求分析、审查、验收时跳过编码，返回当前状态。
2. 外部实现流程能遵守所选路径且策略允许时：`Call the Skill tool with "implement"`。没有 Skill 调用器时，读取同套件的 `../implement/SKILL.md` 并按其执行。。以 Spec 为入口且仅另一名称可用时：`Call the Skill tool with "implement-spec"`。没有 Skill 调用器时，读取同套件的 `../implement-spec/SKILL.md` 并按其执行。。一次只选择一个；缺失、受限或会强制增加未选步骤时，在当前范围内直接完成最小实现。
3. 保持变更足够小。已有独立任务且具备子 Agent 与隔离工作树时按需并行，主实现者负责集成；否则顺序实现。
4. 失败原因不清或出现性能回退时：`Call the Skill tool with "diagnosing-bugs"`。没有 Skill 调用器时，读取同套件的 `../diagnosing-bugs/SKILL.md` 并按其执行。。缺失或受限时，从现有证据提出可区分的假设并做最小验证，再修复原因；契约或环境问题单独反馈。
5. 完成检查：变更对应所选目标、依赖已集成、修改范围清楚。返回变更摘要、已有实际检查结果与待验证部分；修复指出哪些原验证受影响。实现完成不等于验收通过，预期仍来自业务契约。
6. 单独使用到本步结果为止，不自动发布或扩展需求。提示见 [prompts.md](prompts.md)。
