# 需求对齐

> 来源见 README「来源」小节；本文件的独立入口、提示和检查字段为（推断）。

1. 接收需求、相关文档、反馈和代码；先读取能回答问题的材料。已有明确目标、边界与验收依据时，复用后结束。
2. 可调用且策略允许时：`Call the Skill tool with "grilling"`。没有 Skill 调用器时，读取同套件的 `../grilling/SKILL.md` 并按其执行。。没有该 Skill 或不能调用时，围绕目标、边界、取舍和验收连续追问，优先处理会改变实现的问题。
3. 区分已确认结论、材料冲突与待确认假设。预期结果来自业务契约，工具只负责提供证据；代码当前行为不自动成为需求。
4. 当剩余问题已不会显著改变实现方向和验收结果时，输出问题、范围、关键决策、验收目标及其来源；按需更新已有 Spec 或 `CONTEXT.md`。关键问题仍未解决则返回待确认事项，不强行定稿。
5. 完成检查：验收目标能说明怎样判断结果，关键冲突已解决或明确阻塞。单独使用到此结束；复制提示见 [prompts.md](prompts.md)。
