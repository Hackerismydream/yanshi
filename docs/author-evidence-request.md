# 从最近一两周会话补材料

窗口按本次设计日期为 2026-09-30 至 2026-10-14。只提交愿意保存和公开的脱敏内容；公司名、内部链接、账号凭据、客户信息不入库。无需补一份事后编写的“完美流程”，原始转折更有用。

| 材料 | 最少需要的原始内容 | 能补哪处 |
|---|---|---|
| 反复手打的 Prompt | 原句、每次日期、当时任务、实际采用或拒绝的回答；没有次数证据就不填次数 | 触发句与通用实践，不再用模型改写冒充习惯 |
| 最近一次卡住或修坏 | 最初失败、错误修复、你怎样打断、最后确定的原因和验证结果 | debug 目前最薄的内容 |
| 一个测试绿灯但业务不对 | 已确认契约、当时通过的检查、真实路径的偏差、修复后证据 | check / E2E 的真实例子 |
| 一次有作用的思维快捷键 | 采用哪句、原方案、反例或实验、最终保留和删掉什么 | first / challenge / trim / ablate / boundary |
| 一次换会话 | 实际交接 Prompt、接手后的第一步、丢失的信息或顺利接续的证据 | handoff 的必需字段，而非猜测字段 |
| 一个真的反复使用的 SOP | 已有启动、准备数据、读取状态、清理方法及其实际执行记录；凭据只给获取方式 | 项目环境经验与 retro |
| 一条沉淀后仍被用到的规则 | 真实翻车、规则文本、下一次命中、之后有没有过期或冲突 | 验证项目经验不是越堆越多 |

每次使用 docs/author-practices.md 或 retro/practice-template.md 的四项格式。作者没有说过的句子不能放进“作者原话”；原文用于解释的数字不能填“真实例子”。

已有真实材料：本会话中作者反复要求检查最终 ZIP 的纠正。未找到足以新增专属排障案例的可核实记录，故不以概括记忆填空。
