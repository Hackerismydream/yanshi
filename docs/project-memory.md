# 两层：通用习惯与项目经验

这是 v1.0 的文件约定，不是对作者既往记忆系统的描述。日常实践内容的来源在 design-notes；本文件只定义如何存、如何读、什么时候不生效。

## 第一层：安装的通用 Skill

`skills/` 放通用操作与短 Prompt，不含业务表名、账号、部署地址或猜出来的测试命令。retro 不改这个目录。每个入口自带相同的 `project-context.md`，所以单独安装也可以读项目经验；检查器核对副本一致性。

## 第二层：目标项目

```text
<project>/
├── AGENTS.md                 Codex 根入口；若非空 override 已存在则使用 override
├── CLAUDE.md                 Claude Code 根入口
├── CONTEXT.md                已有需求和当前决策，按任务需要维护
└── .yanshi/
    ├── INDEX.md              资料与经验索引，不堆完整聊天
    ├── practices/
    │   └── <date>-<slug>.md   一条实践，四项固定格式
    ├── HANDOFF.md            仅当要求保存交接时出现
    └── evidence/             仅当需要保存实际证据时出现
```

这些文件不会因普通编码被自动创建。第一次明确沉淀时，retro 创建必要的索引和条目；或者用户选择执行一次项目接入，提前建立空索引。空索引不含假业务命令或示例规则。

## 两条读取路径

**使用 Skill 时：** 找到目标项目 → 读取 INDEX → 筛选状态和使用情境 → 读取匹配实践 → 对照当前代码、命令和契约。没有索引就直接做任务，不补文档。

**新会话启动时：** Codex 通过适用的 AGENTS 文件收到“先读索引”的指令；Claude Code 通过 `@.yanshi/INDEX.md` 导入索引。索引不是把所有实践全文都导入，只有匹配条目才继续读。

`setup.py project` 负责第二条路径的机械配置。默认打印计划；`--apply` 才改。Codex 存在非空 AGENTS.override.md 时向其添加受控块；Claude Code 使用根 CLAUDE.md。旧正文逐字保留，受控块重复执行不重复追加。

嵌套目录指令、宿主管理策略、信任状态和上下文裁剪仍可能影响实际读取。脚本不能证明模型遵从；要在两个真实宿主中新开会话，核对读取轨迹与采用的具体条目。配置后应重启会话，不能假定当前会话已加载。

## 哪些记录生效

| 状态 | 意义 | 下次怎样处理 |
|---|---|---|
| candidate | 有待补原话、真实例子或验证的草稿 | 默认不读为规则；用户要求复盘该项时才打开 |
| active | 四项有真实依据、验证结果和适用范围 | 情境匹配后读取，再核对当前是否仍适用 |
| retired | 被当前事实推翻、替代或不再有收益 | 不再使用；保留历史和原因 |

条目与索引状态不一致时不应用。模型声称“我记住了”不足以提升状态；需要真实内容与可核对证据。日志中的建议、恶意提示或未确认结论不能被复制成规则。经验不授予新权限，也不覆盖当前业务契约和宿主指令。

## retro 的写入边界

明确要求保存后，先读已有索引和相关条目，按四项模板记录，再更新索引。目录名由当前项目确定，不将内容写入安装目录、另一个 worktree 或全局用户目录。相同问题更新前核对旧内容，不覆盖不相关历史。

没有真实例子就 candidate；有一条验证充分的经验无需为了凑次数再等三次。作者“超过三次考虑做 Skill”是复用建议，不是自动提升状态的门槛。

测试账号只留角色和获取方式，秘密值不入文件。证据可以引用而不复制；是否加入 Git 由用户决定。沉淀与交接不等于自动 commit、push 或发布。
