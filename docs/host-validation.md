# 双宿主本地验收

这是一份待执行的宿主验收说明。下列人工夹具仅用来检查安装、调用和记忆边界，不是真实作者事故，也不能作为产品效果案例。

## 准备

记录 Codex 与 Claude Code 的实际版本、安装来源、运行目录、权限及本次批准的费用预算。沿用用户已配置的正常登录，不导出凭据，不绕过授权，也不写死模型。没有某宿主、登录或预算则记录具体阻塞，不伪装执行。

在独立临时测试仓库安装本地包，不覆盖用户全局 Skill。先用本机 `--help` 确认非交互调用与输出选项，或在实际交互会话中测试；不复制未核对的 CLI 参数。保留终端原始输出和工具读取轨迹。

## 每个宿主都做

| 检查 | 输入或操作 | 需要的证据 |
|---|---|---|
| 全部名字可发现 | 检查 12 个 Skill 的实际可用列表 | 宿主发现记录，而非 ls 截图 |
| 自然语言选路 | 使用 docs/usage.md 的六个日常说法，中文和英文各覆盖 | 选中的入口、实际读取的 SKILL.md、错选保留 |
| 小改动直做 | 给一项可在临时仓库完成的局部变更 | 没有额外 Spec/任务表，实际改动与检查 |
| 只读边界 | 提交前检查并明确“不改代码” | 操作轨迹与前后差异证明未修改 |
| 五个快捷键 | 主动用原生名字逐个调用 | 核心 Prompt 动作与输入对应，未自动串五步 |
| 普通问答 | 翻译一段文本或解释普通概念 | 没有无关流程与项目写入 |
| 缺索引 | 在没有 .yanshi 的测试仓库使用 Skill | 不为了调用入口创建目录 |
| 口头 retro | 只要求复盘、不要求保存 | 无项目文件写入 |
| 持久化与下次读取 | 明确保存一个有真实测试证据的本地记录；新会话使用相关入口 | 条目与索引状态一致、实际读取匹配 active 项 |
| 候选/退休不生效 | 人工准备 candidate 与 retired 夹具，不放真实秘密 | 不将其作为工作规则；不得只靠标识判断 |
| 新会话入口 | 执行项目接入，分别重启两个宿主 | AGENTS 或 CLAUDE 的实际加载及索引读取；还要确认没有读无关条目 |
| 冲突或变更 | 改动测试夹具引用的命令或契约 | 不沿用已经失效的经验；旧记录保留 |
| 两层不混写 | 执行一次保存和交接 | 只改测试项目，安装的 Skill 哈希不变 |

## 结果格式

每个宿主记录：版本、测试标识、输入、实际动作、证据位置、passed/failed/blocked/not-run、问题和修复后的新记录。表格写满不是通过；原始轨迹必须存在。

输出标识只证明模型打印了字符串。是否读取项目经验，要看文件读取与实际采用是否对应。是否验收业务成功，要看契约与运行证据。

这些检查完成后，另选作者提供的一条真实业务路径进行日常试用。没有真实业务环境就停在“宿主行为已验证”，不升级成业务收益已验证。
